# TazaBAK: чек-лист демонстрации MVP

Этот документ помогает подготовить TazaBAK к показу на защите.

## 1. Запуск платформы

1. Запустите FastAPI на ноутбуке: `uvicorn app.main:app --reload --host 0.0.0.0 --port 8000`.
2. Откройте второй терминал, перейдите в `frontend` и выполните `npm run dev -- --host 0.0.0.0`.
3. В браузере откройте адрес Vite. Для телефона используйте сетевой адрес ноутбука, а не `localhost`.
4. Откройте диспетчерскую и убедитесь, что API отмечено как доступное.

## 1.1. Прогреть модели до защиты — обязательно

Веса загружаются в память при первом обращении, а не при старте сервера.
Холодный первый запрос перед жюри выглядит как зависшее приложение.

Поэтому **до** демонстрации, один раз:

1. Сдайте одно фото хлеба через интерфейс — это загрузит CLIP.
2. Откройте камеру или загрузите один кадр — это загрузит YOLOv8.

Первый запуск на новой машине ещё и скачивает веса CLIP (около 600 МБ) с
Hugging Face — **нужен интернет один раз**. Дальше модель берётся из локального
кэша `~/.cache/huggingface`, и Wi-Fi для неё уже не нужен. Скачайте заранее,
не в день защиты.

Если показываете из Docker (`docker compose up --build`), прогрев не нужен:
веса запекаются в образ на этапе сборки, и контейнер работает офлайн.

Рекомендации Баки работают и без интернета: без ключа или сети они собираются
детерминированными правилами по тем же посчитанным числам.

## 2. Муниципальный IoT-контур

- ESP32 DevKit отправляет расстояние HC-SR04 и температуру DS18B20 в FastAPI по Wi-Fi.
- Заполнение рассчитывается по расстоянию: 25 см — пустой бак, 7 см — полный бак.
- Температура внутри выше 50 C создаёт критический алерт FIRE_RISK.
- ESP32-CAM передаёт MJPEG-поток; FastAPI сохраняет кадр с рамками YOLOv8 при обнаружении незаконного навала.
- Команда CLOSE_LID доставляется ESP32 через WebSocket и закрывает SG90.
- Команда, отданная выключенному устройству, не теряется: она ждёт в очереди и
  уезжает целиком в момент подключения. Это видно на экране — статус меняется
  с `PENDING` на `ACKED` после подтверждения от платы.
- На экране «IoT управление» одна карточка — собранный прототип. Остальные
  одиннадцать адресов живут на карте и в прогнозе: там для них есть данные, а
  заслонки и камеры у них нет.

## 3. Сценарий для показа

1. Войдите диспетчером — сразу открывается экран «Экономия» с суммой в тенге
   и килограммами CO₂. Разверните блок «Откуда цифра»: там та же формула с
   подставленными числами, это лучший ответ на вопрос «откуда экономия».
2. «Прогноз» объясняет, почему ехать нужно не по графику: у каждой площадки
   свой срок до порога. Площадки, где замеров мало, честно говорят об этом
   вместо выдуманной цифры — на этом стоит задержаться.
3. «Доходы», переключите масштаб на «Кокшетау». Это заготовленный ответ на
   вопрос «а как вы на этом заработаете»: пять источников, у каждого рядом
   основание, проекция отдельно помечена как расчёт, а не факт.
4. Житель фотографирует сухой хлеб и получает решение, QR-код и Eco-баллы.
   На экране видно, с какими описаниями CLIP сравнил фото и с какой
   уверенностью — удобный момент показать, что модель объяснима.
5. Диспетчер видит состояние контейнера и изображение с ESP32-CAM.
6. Камера фиксирует посторонний объект у бака, появляется ILLEGAL_DUMP.
7. Волонтёр берёт задачу по уборке и получает баллы после подтверждения.
8. При переполнении диспетчер отправляет команду закрытия заслонки.
9. Кабинет пекарни: внесите вечерние списания и покажите прогноз на завтра.
   График по дням недели объясняет, почему прогноз считается по тому же дню,
   а не по вчерашнему: на выходных остаётся заметно больше.

## 4. Резервный план

- Подготовьте записанное видео MVP на случай отсутствия Wi-Fi.
- Не храните ключи API, пароли Wi-Fi или локальную базу SQLite в публичном репозитории.
- Перед защитой проверьте питание сервопривода от отдельного 5V источника с общей землёй GND.
