# Развёртывание TazaBAK EcoFin

Два разных стенда, и это осознанно.

| | Облако (Render) | Ноутбук (Docker) |
|---|---|---|
| Кому | жюри, ссылка в заявке | защита, живой показ |
| База | PostgreSQL 16 у платформы | PostgreSQL 16 в контейнере |
| Разбор фото хлеба | Gemini по сети | CLIP на самой машине, офлайн |
| YOLOv8 по кадрам камеры | нет | есть, веса запечены в образ |
| Загруженные снимки | исчезают при перезапуске | лежат в томе |
| Первый отклик | до минуты после сна | сразу |

Причина разделения одна: CLIP и YOLOv8 вместе занимают около 700 МБ
оперативной памяти, а бесплатный инстанс Render даёт 512 МБ. Класть их туда
означало бы получить процесс, убитый по OOM на первом же снимке.

Но кнопка «сдать хлеб» — первое, что пробует любой человек, и мёртвой она быть
не может. Поэтому вопрос из трёх вариантов там задаётся Gemini по сети: памяти
это не стоит нисколько. Порядок движков задан в `app/services/bread_vision.py`:
где CLIP установлен, в сеть не ходят вовсе — стенд на защите обязан работать
без Wi-Fi.

Доказательства у движков разные, и интерфейс это не скрывает. CLIP считает
softmax по косинусным близостям — собственное распределение модели. Языковая
модель сообщает уверенность сама. Под вероятностями на экране стоит имя того
движка, который их дал.

## Облако: Render

### Что создаётся

`render.yaml` описывает три сервиса на бесплатных планах:

- `tazabak-db` — PostgreSQL 16, наружу закрыт;
- `tazabak-api` — FastAPI под uvicorn, зависимости из `requirements-core.txt`;
- `tazabak-web` — витрина, собранная Vite и отданная статикой.

Адреса подставляются сами: витрина получает имя хоста API в переменную сборки,
API получает имя хоста витрины в список разрешённых источников CORS.

### Порядок

1. Render → **Blueprints** → **New Blueprint Instance** → этот репозиторий →
   **Apply**. Платформа прочитает `render.yaml` и создаст всё три сервиса.
2. Дождитесь, пока `tazabak-api` станет `live`. Первая сборка занимает
   несколько минут: ставятся зависимости и создаётся схема базы.
3. Откройте `tazabak-api` → **Environment** и скопируйте `DISPATCHER_API_KEY`.
   Платформа сгенерировала его сама: `APP_ENV=production` запрещает
   демонстрационный ключ «123». Этот ключ вводится в окне входа диспетчера.
4. Там же впишите `GEMINI_API_KEY`, если хотите живые советы Баки. Без ключа
   советы собираются локальными правилами по тем же посчитанным числам —
   сервис остаётся рабочим, просто формулировки детерминированные.
5. Откройте адрес `tazabak-web`.

### Что помнить перед защитой

- **Инстанс засыпает после 15 минут без запросов.** Первый запрос после сна
  поднимает контейнер примерно за минуту. Откройте ссылку заранее, иначе жюри
  увидит пустой экран и решит, что проект не работает.
- **Бесплатная база живёт 30 дней** с момента создания. Для хакатона хватает.
- **Диск временный.** Снимки, загруженные через интерфейс, исчезают при
  перезапуске. Строки в базе остаются: они в PostgreSQL, а не на диске.

### Проверка после развёртывания

```bash
curl https://<адрес-api>/health
# {"status":"ok","database":"reachable","image_analysis":"remote"}
```

`image_analysis` принимает три значения: `local` — считает CLIP на этой машине,
`remote` — считает Gemini по сети, `unavailable` — нет ни моделей, ни ключа, и
тогда витрина честно говорит об этом вместо кнопки, ведущей в тупик.

## Ноутбук: Docker

Полный стенд со всеми моделями:

```bash
docker compose up --build
```

Витрина — <http://localhost:5173>, документация API — <http://localhost:8000/docs>.

Первая сборка долгая: ставится torch и запекаются веса YOLOv8 и CLIP. Зато
контейнер потом работает офлайн — на защите Wi-Fi может не быть, а холодный
запрос иначе ушёл бы качать 600 МБ с Hugging Face и выглядел бы как зависшее
приложение.

Переменные берутся из окружения; пароль базы задаётся через `POSTGRES_PASSWORD`,
ключ Gemini — через `GEMINI_API_KEY`. Значения по умолчанию годятся только для
локального стенда.

## Почему два файла зависимостей

- `requirements-core.txt` — всё, что нужно сервису, кроме счёта моделей на этой
  же машине. Ставится в облаке.
- `requirements.txt` — ядро плюс `ultralytics` и `transformers`. Ставится на
  ноутбуке, в Docker и в CI, чтобы тесты проверяли ровно тот код, который
  поедет на защиту.

Второй файл ссылается на первый, поэтому список не раздваивается.
