# Железо TazaBAK: что куда подключать и как запускать

Пошагово, от голых плат до работающего бака. Всё, что здесь написано, взято из
кода проекта, а не из общих рекомендаций: номера пинов — из
`firmware/municipal_esp32/municipal_esp32.ino`, пороги — из `app/config.py`.

---

## 1. Что нужно

| Компонент | Зачем | Примечание |
|---|---|---|
| ESP32 DevKit v1 | мозг бака | с USB — прошивается напрямую |
| HC-SR04 | расстояние до мусора | питание строго 5 В |
| DS18B20 | температура внутри | нужен резистор 4.7 кОм |
| SG90 | заслонка | **своё питание 5 В**, см. §2.4 |
| Резистор 4.7 кОм | подтяжка DS18B20 | без него датчик молчит |
| Резисторы 1 кОм и 2 кОм | делитель для Echo | без него можно сжечь вход |
| ESP32-CAM (AI-Thinker) | камера у бака | **USB нет**, нужен переходник |
| USB-TTL переходник | прошить ESP32-CAM | CP2102 / CH340, обязательно 5 В и 3.3 В |
| Провода, макетка, блок питания 5 В 2 А | | |

## 2. Основной бак: ESP32 DevKit

### 2.1. Таблица подключения

| Устройство | Вывод | ESP32 |
|---|---|---|
| DS18B20 | DATA | **GPIO 4** |
| DS18B20 | VCC | 3V3 |
| DS18B20 | GND | GND |
| DS18B20 | между DATA и VCC | резистор **4.7 кОм** |
| HC-SR04 | Trig | **GPIO 5** |
| HC-SR04 | Echo | **GPIO 18** — только через делитель |
| HC-SR04 | VCC | **5V (VIN)**, не 3V3 |
| HC-SR04 | GND | GND |
| SG90 | сигнал | **GPIO 13** |
| SG90 | питание | отдельные 5 В |
| SG90 | GND | общий с ESP32 |

### 2.2. Делитель для Echo — не пропускайте

HC-SR04 отдаёт на Echo 5 вольт, а вход ESP32 рассчитан на 3.3. Прямое
подключение выводит пин из строя не всегда сразу — иногда через день.

```
Echo ──[ 1 кОм ]──┬── GPIO 18
                  │
              [ 2 кОм ]
                  │
                 GND
```

Пять вольт превращаются в 3.3. Два обычных резистора, полминуты работы.

### 2.3. DS18B20 без подтяжки не работает

Резистор 4.7 кОм между DATA и VCC обязателен: шина 1-Wire без него не
подтягивается в единицу, и датчик читается как отключённый. В коде это видно
как `Telemetry skipped: DS18B20 is disconnected`.

### 2.4. Сервопривод от отдельного питания

SG90 в момент поворота потребляет до 700 мА. Взять их с пина 5V платы —
получить просадку и перезагрузку ESP32 ровно в момент закрытия заслонки, то
есть при пожарной тревоге.

Отдельный источник 5 В, **земля общая с ESP32** — без общей земли сигнал не
имеет опорной точки, и привод дёргается случайным образом.

### 2.5. Калибровка

Бак глубиной 25 см. Backend считает 25 см пустым баком, 7 см — полным
(`H_EMPTY_CM` и `H_FULL_CM` в `.env`). Если ваш макет другой глубины —
меняйте эти два значения, а не код.

Температура **выше 50 °C** создаёт критический алерт `FIRE_RISK`, и backend
сам отправляет команду закрытия заслонки.

## 3. Прошивка основного бака

Arduino IDE → Инструменты → Плата → **ESP32 Dev Module**.

Библиотеки (Менеджер библиотек):

- `OneWire`
- `DallasTemperature`
- `ESP32Servo`
- `ArduinoJson`
- `WebSockets` (Markus Sattler / Links2004)

Откройте `firmware/municipal_esp32/municipal_esp32.ino` и заполните начало:

```cpp
constexpr char WIFI_SSID[] = "имя вашей сети";
constexpr char WIFI_PASSWORD[] = "пароль";
constexpr char DEVICE_ID[] = "municipal-prototype-001";

#define TAZABAK_CLOUD 0   // 0 — ноутбук рядом, 1 — облако
```

При `TAZABAK_CLOUD 0` укажите ещё и адрес ноутбука:

```cpp
constexpr char BACKEND_HOST[] = "192.168.1.100";  // IP ноутбука в вашей сети
```

IP ноутбука: `ipconfig` в Windows, строка «IPv4-адрес» у активного адаптера.
Он меняется при переподключении к Wi-Fi — проверьте перед показом.

Прошейте. В мониторе порта (115200) должно появиться:

```
Wi-Fi connected. ESP32 IP: 192.168.1.105
Telemetry: distance=16.20 cm, DS18B20=22.50 C, HTTP=200
```

`HTTP=200` — замер принят. Любой другой код или `-1` — §8.

## 4. ESP32-CAM: подключение и прошивка

Отдельная плата. У AI-Thinker **нет USB**, прошивается через USB-TTL
переходник.

### 4.1. Схема прошивки

| USB-TTL | ESP32-CAM |
|---|---|
| 5V | **5V** |
| GND | GND |
| TX | **U0R** (RX) |
| RX | **U0T** (TX) |
| — | **IO0 ↔ GND** перемычкой |

Три вещи, на которых спотыкаются все:

1. **TX идёт в RX, RX в TX.** Соединять одноимённые бесполезно.
2. **IO0 замкнут на GND** — только так плата входит в режим прошивки.
   После прошивки перемычку снять и нажать RESET.
3. **Питание 5 В, не 3.3.** На 3.3 плата стартует и падает при включении
   камеры: пикового тока не хватает.

Переходник обязательно должен уметь 5 В — многие дешёвые дают только 3.3.

### 4.2. Что прошивать

Своей прошивки в проекте нет и не нужно: подходит штатный пример.

Arduino IDE → Файл → Примеры → **ESP32 → Camera → CameraWebServer**

В скетче:

- раскомментируйте `#define CAMERA_MODEL_AI_THINKER`, остальные модели
  закомментируйте;
- впишите `ssid` и `password` — **ту же сеть, что у ноутбука и основного бака**;
- Плата: **AI Thinker ESP32-CAM**.

Прошейте, снимите перемычку IO0, нажмите RESET. В мониторе порта:

```
Camera Ready! Use 'http://192.168.1.106' to connect
```

Проверьте в браузере: `http://192.168.1.106` — должна открыться страница с
кнопкой Start Stream.

### 4.3. Два адреса камеры

Пример поднимает **два порта**, и это важно:

| Адрес | Что отдаёт | Кто использует |
|---|---|---|
| `http://<ip>/capture` | один кадр JPEG | YOLOv8 в backend |
| `http://<ip>:81/stream` | поток MJPEG | картинка в интерфейсе |

Backend принимает адрес потока и сам выводит из него адрес кадра
(`capture_url_from_stream` в `app/services/camera_vision.py`), поэтому вводить
нужно **один** адрес — со `:81/stream`.

### 4.4. Привязать камеру к баку

1. Войдите диспетчером: `dispatcher-1` / `123`, ключ `123`.
2. **IoT управление** → карточка бака → кнопка **Камера**.
3. Вставьте адрес потока:

```
http://192.168.1.106:81/stream
```

4. Сохраните.

Дальше backend раз в 5 секунд забирает кадр, прогоняет через YOLOv8 и при
трёх и более посторонних предметах создаёт алерт `ILLEGAL_DUMP`. Интервал и
порог — `CAMERA_ANALYSIS_INTERVAL_SECONDS` и `CAMERA_ILLEGAL_DUMP_MIN_OBJECTS`
в `.env`.

### 4.5. Камера и облако — так не работает

**Камера работает только с локальным стендом.**

Backend сам ходит на адрес камеры за кадром. Адрес `192.168.1.106` — из вашей
домашней сети, из интернета он недоступен: между ними роутер с NAT. Облачный
сервис постучится в пустоту и получит `502 ESP32-CAM stream is unavailable`.

Это ограничение схемы, а не ошибка. Если камеру нужно показать через облако —
единственный рабочий путь — обратный: кто-то в локальной сети шлёт кадр
**сам**, POST на `/api/vision/frame`. Тот же YOLOv8, то же правило, тот же
алерт. Скрипта для этого в проекте пока нет.

На защите держите камеру на локальном стенде — там она работает целиком.

## 5. Запуск backend и frontend

### Вариант А — Docker (проще, всё сразу)

```bash
docker compose up --build
```

Поднимет PostgreSQL, backend и интерфейс. Первая сборка долгая: ставится torch
и в образ запекаются веса YOLOv8 и CLIP — зато потом работает без интернета.

- интерфейс: <http://localhost:5173>
- API: <http://localhost:8000/docs>

### Вариант Б — вручную

Два терминала.

```bash
# первый
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

```bash
# второй
cd frontend
npm install
npm run dev -- --host 0.0.0.0
```

**`--host 0.0.0.0` обязателен в обоих.** Без него сервер слушает только
`localhost`, и ESP32 из сети до него не достучится.

### Брандмауэр Windows

При первом запуске Windows спросит про доступ к сети — разрешите для **частных
сетей**. Если пропустили окно, ESP32 будет получать `HTTP=-1`, а на ноутбуке
всё будет выглядеть работающим.

## 6. Проверка по шагам

Делайте по порядку, не пропуская — каждый шаг проверяет ровно одно звено.

1. **ESP32 подключился к Wi-Fi** — в мониторе порта есть IP.
2. **Замеры доходят** — в мониторе `HTTP=200` каждые 15 секунд.
3. **Backend видит бак** — интерфейс, IoT управление: карточка показывает
   температуру и отметку **«на связи»**. Если написано «молчит N мин» —
   замеры не доходят, возвращайтесь к шагу 2.
4. **Заслонка слушается** — кнопки «Открыть» и «Закрыть» на карточке.
   Привод должен повернуться, а в мониторе порта появиться `Command received`.
5. **Камера отдаёт картинку** — кнопка «Камера», изображение в окне.
6. **Пожарная блокировка** — зажмите DS18B20 пальцами или поднесите тёплое.
   Выше 50 °C: появляется алерт `FIRE_RISK`, заслонка закрывается сама.

## 7. Что работает где

| | Локальный стенд | Облако |
|---|---|---|
| Приём замеров | да | да, HTTPS |
| Команды заслонки | да | да, WSS |
| Разбор фото хлеба | CLIP на машине | Gemini по сети |
| **Камера ESP32-CAM** | **да** | **нет**, §4.5 |
| Показ без ноутбука | нет | да |
| Зависимость от интернета | нет | да |

Для защиты надёжнее **локальный стенд**: не зависит от Wi-Fi в зале и от
пробуждения бесплатного инстанса, которое занимает около минуты.

## 8. Если не работает

**`HTTP=-1` в мониторе порта.** Замер не ушёл. По очереди: ESP32 и ноутбук в
одной сети; `BACKEND_HOST` — текущий IP ноутбука; uvicorn запущен с
`--host 0.0.0.0`; брандмауэр не блокирует. Проверить с телефона в той же сети:
`http://192.168.1.100:8000/health` должен ответить.

**`DS18B20 is disconnected`.** Нет подтяжки 4.7 кОм, либо перепутаны VCC и
DATA, либо плохой контакт на макетке.

**`invalid HC-SR04 distance`.** Датчик питается от 3.3 вместо 5 В, либо
перепутаны Trig и Echo, либо до поверхности меньше 2 см — ближе HC-SR04 не
измеряет.

**ESP32 перезагружается при повороте заслонки.** Привод питается от платы.
Отдельный источник 5 В, земля общая.

**Камера: `502 ESP32-CAM stream is unavailable`.** Адрес недоступен backend.
Проверьте, что открывается в браузере с ноутбука, что в адресе есть `:81/stream`,
и что backend локальный, а не облачный (§4.5).

**ESP32-CAM не прошивается.** IO0 не замкнут на GND, либо TX/RX не
перекрещены, либо питание 3.3 вместо 5 В. После прошивки перемычку снять.

**Карточка бака показывает «молчит».** Замеры не доходят более трёх минут —
это двенадцать пропущенных отправок подряд. Смотрите монитор порта.
